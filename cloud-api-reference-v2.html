Overview

The Dividia Cloud NVR API provides REST endpoints for integrating with cloud-connected video surveillance systems. This API enables third-party applications to authenticate users, retrieve device and camera information, and stream live video.

Base URL

https://api.cloud.dividia.net

Authentication Method

The Cloud API uses JWT (JSON Web Tokens) for authentication. After login, include the token in all authenticated requests:

Authorization: Bearer <your-jwt-token>

1. Authentication

POST /ve/auth

Authenticates a user and returns a JWT token along with all authorized devices and cameras.

POST /ve/auth

Request Body

{
  "username": "user@example.com",
  "password": "your-password"
}

Request Parameters

FieldTypeRequiredDescription
usernamestringYesUser email address
passwordstringYesUser password

Success Response

{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "devices": [
    {
      "sDeviceID": "A1B2C3D4E5F6",
      "sName": "Front Lobby NVR",
      "fOnline": 1
    }
  ],
  "cameras": [
    {
      "sDeviceID": "A1B2C3D4E5F6",
      "bCamera": 1,
      "bProfile": 2,
      "sName": "Front Door",
      "fEnabled": 1,
      "fOnline": 1
    }
  ]
}

Response Fields

FieldTypeDescription
tokenstringJWT token for authenticated requests (valid 30 days)
devicesarrayRecording devices user has access to (see Device Object below)
camerasarrayCameras available for streaming (see Camera Object below)

Error Response

// Invalid credentials
{"error": "Could not find user."}

// Password change required
{"changePassword": true, "user": {...}}
Important: The login response includes all devices and cameras the user has access to for streaming. No separate API call is needed to fetch cameras or build WebSocket URLs.

Token Usage

Include the JWT token in the Authorization header for all authenticated endpoints:

GET /ve/streamstart?device=A1B2C3D4E5F6&cam=1&pro=1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Token Expiry: JWT tokens are valid for 30 days. When the token expires, re-authenticate with /ve/auth.

2. Data Model

Streaming Hierarchy

Device (Recording Unit)
  └── Camera (Video Stream)

The login response returns devices and cameras authorized for the user. Each camera belongs to a device, and the WebSocket URL is constructed from device and camera IDs.

Device Object

FieldTypeDescription
sDeviceIDstringUnique device serial (e.g., "A1B2C3D4E5F6") - used in WebSocket URL
sNamestringDevice display name
fOnlineintOnline status: 1 = online, 0 = offline

Camera Object

FieldTypeDescription
sDeviceIDstringParent device serial - links camera to device
bCameraintCamera number on device (1-16) - used in WebSocket URL as cam{N}
bProfileintStream profile (1 = full res, 2 = lower res) - used in WebSocket URL as pro{P}
sNamestringCamera display name
fEnabledintEnabled status: 1 = enabled, 0 = disabled
fOnlineintOnline status: 1 = online, 0 = offline
WebSocket URL Construction: Use the device, camera fields and JWT token to build the streaming URL:
wss://api.cloud.dividia.net/{sDeviceID}-cam{bCamera}-pro{bProfile}?token={token}

3. Live Video Streaming

For low-latency live streaming, the Cloud API supports WebSocket-based H.264 streaming using the browser's WebCodecs API for hardware-accelerated decoding.

WS wss://api.cloud.dividia.net/{deviceID}-cam{N}-pro{P}?token={token}
Authentication Required: The token query parameter is required. The JWT token from /ve/auth must be included in the WebSocket URL. Connections without a valid token will be rejected with code 1008 (Policy Violation).

URL Parameters

ParameterTypeDescription
deviceIDstringDevice serial ID from /ve/devices
NintCamera number (1, 2, 3...)
PintVideo profile: 1 (full resolution) or 2 (lower resolution)
tokenstringJWT token from /ve/auth

Example URLs

// Full resolution stream
wss://api.cloud.dividia.net/A1B2C3D4E5F6-cam1-pro1?token=eyJhbGciOiJIUzI1Ni...

// Lower resolution for multi-camera grids
wss://api.cloud.dividia.net/A1B2C3D4E5F6-cam1-pro2?token=eyJhbGciOiJIUzI1Ni...
Protocol: Always use wss:// (secure WebSocket) as the Cloud API requires HTTPS.

Using WSPlayer.js (Recommended)

The easiest way to integrate WebSocket H.264 streaming is using the WSPlayer.js library. It's a fully self-contained component that generates all HTML (canvas, overlays, loading spinner, stats) inside a container element.

// Include the WSPlayer.js library
<script src="WSPlayer.js"></script>

<!-- Just provide an empty container - WSPlayer generates all HTML inside -->
<div id="camera-1" style="width: 640px; height: 480px;"></div>

<script>
// Build WebSocket URL from device/camera/token info
const deviceId = 'A1B2C3D4E5F6';  // From /ve/auth response
const token = 'eyJhbGciOiJIUzI1Ni...';  // JWT token from /ve/auth
const wsUrl = `wss://api.cloud.dividia.net/${deviceId}-cam1-pro1?token=${encodeURIComponent(token)}`;

// Create and start player using the factory method
const player = WSPlayer.create('camera-1', {
    url: wsUrl,
    camera: [1, 'Front Door'],  // [cameraId, cameraName]

    // Optional: event callbacks
    onConnect: () => console.log('Connected'),
    onFirstFrame: () => console.log('Video started'),
    onError: (err) => console.error('Error:', err),
    onDisconnect: () => console.log('Disconnected'),
    onReconnecting: () => console.log('Reconnecting...'),
    onStall: () => console.log('Stream stalled'),
    onMetadata: (data) => console.log('Metadata:', data)
});

// Control methods
player.stop();      // Stop streaming
player.start();     // Start streaming
player.restart();   // Restart streaming

// Status methods
player.connected();       // Returns true/false
player.getFrameCount();   // Returns number of frames decoded
player.getFPS();          // Returns current FPS
player.getStatus();       // Returns full status object
</script>
Multiple Cameras Example
// Create players for multiple cameras from a device
cameras.forEach(cam => {
    const wsUrl = `wss://api.cloud.dividia.net/${deviceId}-cam${cam.bCamera}-pro2?token=${encodeURIComponent(token)}`;
    WSPlayer.create(`cam-${cam.bCamera}`, {
        url: wsUrl,
        camera: [cam.bCamera, cam.sName],
    });
});

WSPlayer.js Features:

  • Self-contained HTML generation - canvas, overlays, loading spinner, stats all generated internally
  • Automatic H.264 codec detection
  • Hardware-accelerated decoding via WebCodecs
  • Auto-reconnect on disconnect with configurable delay
  • Stall detection with callback notification
  • Built-in loading spinner and connection status
  • Camera name, FPS/frame stats, and timestamp overlays
  • Debug mode with detailed logging

Static Methods:

// Check if WebCodecs is supported before creating player
const support = WSPlayer.checkSupport();
if (!support.supported) {
    console.error(support.reason);
}

// Factory method (auto-starts the player)
const player = WSPlayer.create('container-id', options);
Custom Implementation: If you need to implement WebSocket H.264 streaming without using WSPlayer.js, refer to the WSPlayer.js source code for a complete working implementation including codec detection and decoder management.
Secure Context Required: WebCodecs API only works in secure contexts:
  • HTTPS - https://yourapp.com
  • localhost - http://localhost (development exception)
Codec Support: Cameras may use different H.264 profiles (Baseline, Main, High). WSPlayer.js detects and handles all supported profiles automatically.
Browser Requirements: WebSocket H.264 requires modern browser support for the WebCodecs API:
  • Chrome 94+ / Edge 94+
  • Safari 16.4+
  • Firefox: Not supported (no WebCodecs)
Error Recovery: WSPlayer.js automatically handles decoder errors, hardware/software fallback, and stream recovery. It will attempt hardware decoding first and fall back to software decoding if needed.
Advantages: WebSocket H.264 offers low bandwidth usage, lowest latency, and hardware-accelerated decoding. Use WSPlayer.js for the simplest integration.

Analytics Metadata (Objects, LPR & POS)

On analytics-capable devices, the same live WebSocket carries metadata text frames interleaved with the binary video. Each text (string) frame is a JSON object describing what the device sees right now: detected objects, license-plate reads, and point-of-sale register text. WSPlayer.js draws these on the video and, when given a MessageQueue, publishes them as structured events for your application to consume.

Device requirement: Object / LPR / POS metadata is produced by analytics-capable devices. A standard recorder emits only { "camname", "time" } in its metadata frames (no objects/lpr/pos). The Cloud relay forwards whatever the device sends through unchanged — no extra Cloud API call or parameter is required to receive metadata.

Metadata Frame Schema

The stream interleaves two frame types on one socket: binary frames (H.264/H.265 video) and text frames (the JSON below). All coordinates are normalized to [0..1] relative to the frame, so they scale to any canvas size.

{
  "camname": "Front Lot",
  "time": "2026-06-25 14:03:21",

  "objects": [
    { "id": "42", "label": "car", "description": "white sedan",
      "bbox": [0.31, 0.40, 0.18, 0.22] }        // [x, y, w, h] normalized
  ],

  "lpr": {
    "state": "HIT",                              // WAITING | DETECTING | HIT
    "plate": "ABC1234",                          // confirmed plate (on HIT)
    "roi": [0.0, 0.0, 1.0, 1.0],                 // region the LPR scans
    "results": [
      { "plate": "ABC1234", "confidence": 0.93, "region": "us-tx",
        "coordinates": [ {"x":0.33,"y":0.42}, {"x":0.41,"y":0.42},
                         {"x":0.41,"y":0.47}, {"x":0.33,"y":0.47} ] }
    ]
  },

  "pos": [
    { "terminal": 1, "name": "Register 1",
      "lines": ["ITEM 001      2.99", "TOTAL         2.99"] }
  ]
}
FieldTypeDescription
camnamestringCamera display name
timestringFrame timestamp from the device
objects[]arrayDetected objects: id = tracking id, label = class, description = optional text, bbox = [x,y,w,h] normalized
lprobjectLicense-plate state: state = WAITING / DETECTING / HIT; plate = confirmed read; roi = scan rectangle; results[] = candidates
lpr.results[]arrayplate, confidence (0..1), region, and coordinates (4 corner points, normalized)
pos[]arrayPOS registers: terminal, name, and lines[] of receipt text

Consuming Events with a MessageQueue

Include messageQueue.js, create a MessageQueue, and pass it to one or more players via the messageQueue option. The player publishes three event types as detections arrive. A single queue can aggregate events from every camera on the page — one place for an integration to subscribe.

<script src="messageQueue.js"></script>
<script src="WSPlayer.js"></script>

<script>
const mq = new MessageQueue();

mq.subscribe('lprEvent', e => {
    console.log('Plate', e.plate, e.confidence, e.region);
    // e.image is a base64 JPEG of the cropped plate (or null)
});
mq.subscribe('objectEvent', e => console.log('Object', e.label, e.description));
mq.subscribe('posEvent', e => console.log('POS', e.pos));

WSPlayer.create('cam1', {
    url: wsUrl,
    camera: [1, 'Front Lot'],
    messageQueue: mq,        // publish events to the bus
    showObjects: true,       // draw object boxes
    showLpr: true,           // draw plate quads
    showPos: false           // hide POS panel (events still publish)
});
</script>

objectEvent

FieldTypeDescription
idstringObject tracking id (fires once per new id)
labelstringDetected class (e.g. "person", "car")
descriptionstringOptional descriptive text, when the device provides it
imagestringBase64 JPEG data URL of the cropped object (or null)

lprEvent

FieldTypeDescription
camnamestringCamera display name
platestringPlate text (confirmed on HIT, else this result's candidate)
statestringDETECTING or HIT
confidencenumberRead confidence (0..1)
regionstringPlate region / jurisdiction
coordinatesarray4 corner points {x,y}, normalized
imagestringBase64 JPEG data URL of the cropped plate (or null)
Dedup: lprEvent fires once per (state, plate) transition (DETECTING then HIT), not every frame the plate stays in view.

posEvent

FieldTypeDescription
camnamestringCamera display name
posarrayRegisters { terminal, name, lines:[...] }. Fires when the register text changes
Data is independent of the overlays: events publish to the MessageQueue whether or not the matching overlay is drawn. You can hide the boxes and still receive the data — useful when the video and the data go to different places.

Overlay Display & Filtering

Each overlay type toggles independently. A toggle accepts true, false, or a predicate for per-detection filtering, and can be changed at runtime with setOverlayVisible().

Users can also right-click the video to toggle overlays from a built-in context menu (Show object boxes / license plates / POS). Pass onOverlayChange(type, value) to keep your own UI (e.g. checkboxes) in sync when an overlay is toggled from that menu.

// Toggle at runtime (drawing stops; events keep publishing)
player.setOverlayVisible('lpr', false);

// Predicate: only draw high-confidence plates
WSPlayer.create('cam1', { ..., showLpr: (r) => r.confidence > 0.8 });

// Predicate: only box people and cars
WSPlayer.create('cam1', { ..., showObjects: (o) => ['person', 'car'].includes(o.label) });

PTZ Controls

Set showPtz: true (or toggle "Show PTZ controls" from the right-click menu) to overlay pan/tilt/zoom controls on the video: a 3×3 D-pad with a home button in the center, zoom in/out, and presets 1–4. The player sends commands upstream over the same WebSocket and the connected device acts on them. The Cloud relay forwards client→device messages, so PTZ works over the cloud path too.

Command Protocol

Each control sends a JSON text frame to the server of the form { "type": "ptz", ... }:

ControlMessage(s) sent
Pan / tilt (press & hold){type:"ptz", axis:"x"|"y", value:N} on press, then {..., value:0} on release
Zoom (press & hold){type:"ptz", axis:"z", value:N} on press, then {..., value:0} on release
Diagonal pantwo messages — one x and one y command
Home / preset (one-shot){type:"ptz", preset:"goto", n:0-4} (0 = home)

value is a velocity (the player uses ±80): the device moves while it's non-zero and stops on 0. Use the onPtz callback to mirror or log every command:

const player = WSPlayer.create('cam1', {
    url: wsUrl,
    showPtz: true,
    onPtz: (cmd) => console.log('PTZ', cmd)   // e.g. {axis:'x',value:80} then {axis:'x',value:0}
});

// Toggle the controls at runtime:
player.setOverlayVisible('ptz', true);
Device support: the connected device must understand the ptz message (analytics-capable devices do). A device that doesn't will simply ignore it.

4. Device & Camera Status

GET /ve/onlinestatus

Retrieves the current online status of devices and their cameras.

GET /ve/onlinestatus

Query Parameters

ParameterTypeDescription
idsstringColon-separated device IDs (e.g., "DEV1:DEV2:DEV3")

Example Request

GET /ve/onlinestatus?ids=A1B2C3D4E5F6:0F1E2D3C4B5A
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Response

[
  {
    "sDeviceID": "A1B2C3D4E5F6",
    "fOnline": 1,
    "sBackendID": "backend-01",
    "cams": [
      {"bID": 1, "fEnabled": 1, "fOnline": 1},
      {"bID": 2, "fEnabled": 1, "fOnline": 0}
    ]
  }
]
Polling: Call this endpoint periodically (every 30-60 seconds) to keep status updated in your application.
