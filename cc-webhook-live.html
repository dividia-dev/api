Command Cloud → Dividia: live webhook tester

Sends a real, signed ticket to Dividia the same way your Command Cloud sender will, then reads it back through the public API.

How it works

  1. One HTTPS POST per ticket to https://api.cloud.dividia.net/sw/webhooks/cc, the same URL for every customer. There is no login, session or token: the signature is the authentication.
  2. Four headers. Dividia-Customer-Id is your customer id. The other three are the Standard Webhooks signature: webhook-id is any unique string (this page uses the ticket's uniqueId; it is required because it is part of what is signed), webhook-timestamp is Unix seconds and must be within 5 minutes of our clock, and webhook-signature is v1, + Base64( HMAC-SHA256( key, webhook-id + "." + webhook-timestamp + "." + body ) ). The key is the Base64 value after whsec_ in your secret, decoded. The secret itself is never sent.
    Why v1, comes first: it is the version label of the signing method in the Standard Webhooks format, and v1 means HMAC-SHA256 with your shared secret. The header can carry several signatures separated by spaces, each written as version,signature. We check every v1 signature and accept the ticket if one matches. A signature without v1, in front is ignored, so the request gets a 401.
  3. The body is your ticket JSON, signed byte for byte as sent. location.id picks the site and its NVR. scaleId picks the scale (an exact, case-sensitive match). uniqueId must be new for every ticket: we de-duplicate on it, so a retry of the same ticket is harmless. ticketNumber is required. Everything else (vehicle, carrier, customer, project, product, orderId) rides along on the ticket.
  4. Our answer is HTTP 200 with a status: delivered (the NVR has the ticket and photographs the scale), fallback (stored without images; reason says why), failed (the location.id is not set up) or duplicate (this uniqueId was already received). A 400 or 401 means fix the request. On a 429 or 5xx, retry with the same uniqueId.
  5. Read it back with the public API: your public-API token as Authorization: Bearer <token> (it is emailed to the API user when API access is turned on; it does not expire, so save it and reuse it) on GET /sw/api/tickets?locationId=…&ticket=…, which lists the ticket while it waits on the NVR, and GET /sw/api/tickets/pdf?locationId=…&ticket=…, which returns the ticket's PDF, with images once the NVR has uploaded them (within about two minutes).
