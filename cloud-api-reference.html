Overview

The Dividia Cloud NVR API provides REST endpoints for integrating with cloud-connected video surveillance systems. This API enables third-party applications to authenticate users, retrieve device and camera information, and stream live video.

Base URL

https://api.cloud.dividia.net

Authentication Method

The Cloud API uses JWT (JSON Web Tokens) for authentication. After login, include the token in all authenticated requests:

Authorization: Bearer <your-jwt-token>

1. Authentication

POST /ve/auth

Authenticates a user and returns a JWT token along with all authorized devices and cameras.

POST /ve/auth

Request Body

{
  "username": "user@example.com",
  "password": "your-password"
}

Request Parameters

FieldTypeRequiredDescription
usernamestringYesUser email address
passwordstringYesUser password

Success Response

{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "devices": [
    {
      "sDeviceID": "0A58A9FEAC02",
      "sName": "Front Lobby NVR",
      "fOnline": 1
    }
  ],
  "cameras": [
    {
      "sDeviceID": "0A58A9FEAC02",
      "bCamera": 1,
      "bProfile": 2,
      "sName": "Front Door",
      "fEnabled": 1,
      "fOnline": 1
    }
  ]
}

Response Fields

FieldTypeDescription
tokenstringJWT token for authenticated requests (valid 30 days)
devicesarrayRecording devices user has access to (see Device Object below)
camerasarrayCameras available for streaming (see Camera Object below)

Error Response

// Invalid credentials
{"error": "Could not find user."}

// Password change required
{"changePassword": true, "user": {...}}
Important: The login response includes all devices and cameras the user has access to for streaming. No separate API call is needed to fetch cameras or build WebSocket URLs.

Token Usage

Include the JWT token in the Authorization header for all authenticated endpoints:

GET /ve/streamstart?device=0A58A9FEAC02&cam=1&pro=1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Token Expiry: JWT tokens are valid for 30 days. When the token expires, re-authenticate with /ve/auth.

2. Data Model

Streaming Hierarchy

Device (Recording Unit)
  └── Camera (Video Stream)

The login response returns devices and cameras authorized for the user. Each camera belongs to a device, and the WebSocket URL is constructed from device and camera IDs.

Device Object

FieldTypeDescription
sDeviceIDstringUnique device serial (e.g., "0A58A9FEAC02") - used in WebSocket URL
sNamestringDevice display name
fOnlineintOnline status: 1 = online, 0 = offline

Camera Object

FieldTypeDescription
sDeviceIDstringParent device serial - links camera to device
bCameraintCamera number on device (1-16) - used in WebSocket URL as cam{N}
bProfileintStream profile (1 = full res, 2 = lower res) - used in WebSocket URL as pro{P}
sNamestringCamera display name
fEnabledintEnabled status: 1 = enabled, 0 = disabled
fOnlineintOnline status: 1 = online, 0 = offline
WebSocket URL Construction: Use the device, camera fields and token to build the streaming URL:
wss://api.cloud.dividia.net/{sDeviceID}-cam{bCamera}-pro{bProfile}

3. Live Video Streaming

For low-latency live streaming, the Cloud API supports WebSocket-based H.264 streaming using the browser's WebCodecs API for hardware-accelerated decoding.

WS wss://api.cloud.dividia.net/{deviceID}-cam{N}-pro{P}

URL Parameters

ParameterTypeDescription
deviceIDstringDevice serial ID from /ve/devices
NintCamera number (1, 2, 3...)
PintVideo profile: 1 (full resolution) or 2 (lower resolution)
tokenstringJWT token from /ve/auth

Example URLs

// Full resolution stream
wss://api.cloud.dividia.net/0A58A9FEAC02-cam1-pro1?token=eyJhbGciOiJIUzI1Ni...

// Lower resolution for multi-camera grids
wss://api.cloud.dividia.net/0A58A9FEAC02-cam1-pro2?token=eyJhbGciOiJIUzI1Ni...
Protocol: Always use wss:// (secure WebSocket) as the Cloud API requires HTTPS.

Using WSPlayer.js (Recommended)

The easiest way to integrate WebSocket H.264 streaming is using the WSPlayer.js library. It's a fully self-contained component that generates all HTML (canvas, overlays, loading spinner, stats) inside a container element.

// Include the WSPlayer.js library
<script src="WSPlayer.js"></script>

<!-- Just provide an empty container - WSPlayer generates all HTML inside -->
<div id="camera-1" style="width: 640px; height: 480px;"></div>

<script>
// Build WebSocket URL from device/camera/token info
const deviceId = '0A58A9FEAC02';  // From /ve/devices response

const wsUrl = `wss://api.cloud.dividia.net/${deviceId}-cam1-pro1`;

// Create and start player using the factory method
const player = WSPlayer.create('camera-1', {
    url: wsUrl,
    camera: [1, 'Front Door'],  // [cameraId, cameraName]

    // Optional: event callbacks
    onConnect: () => console.log('Connected'),
    onFirstFrame: () => console.log('Video started'),
    onError: (err) => console.error('Error:', err),
    onDisconnect: () => console.log('Disconnected'),
    onReconnecting: () => console.log('Reconnecting...'),
    onStall: () => console.log('Stream stalled'),
    onMetadata: (data) => console.log('Metadata:', data)
});

// Control methods
player.stop();      // Stop streaming
player.start();     // Start streaming
player.restart();   // Restart streaming

// Status methods
player.connected();       // Returns true/false
player.getFrameCount();   // Returns number of frames decoded
player.getFPS();          // Returns current FPS
player.getStatus();       // Returns full status object
</script>
Multiple Cameras Example
// Create players for multiple cameras from a device
cameras.forEach(cam => {
    const wsUrl = `wss://api.cloud.dividia.net/${deviceId}-cam${cam.bCamera}-pro2`;
    WSPlayer.create(`cam-${cam.bCamera}`, {
        url: wsUrl,
        camera: [cam.bCamera, cam.sName],
    });
});

WSPlayer.js Features:

  • Self-contained HTML generation - canvas, overlays, loading spinner, stats all generated internally
  • Automatic H.264 codec detection
  • Hardware-accelerated decoding via WebCodecs
  • Auto-reconnect on disconnect with configurable delay
  • Stall detection with callback notification
  • Built-in loading spinner and connection status
  • Camera name, FPS/frame stats, and timestamp overlays
  • Debug mode with detailed logging

WSPlayer Options:

OptionTypeDefaultDescription
urlstring-Full WebSocket URL (required)
cameraarray-Camera info as [id, name] array
noOverlayboolean | array-Hide overlays: true = hide all, or array like ['cam_name', 'fps', 'ts']
autoReconnectbooleantrueAuto-reconnect on disconnect
reconnectDelaynumber5000Reconnect delay in milliseconds
stallTimeoutnumber5000Stall detection timeout in milliseconds
debugbooleanfalseEnable debug logging to console

Overlay Control:

WSPlayer displays three overlay elements by default. Use noOverlay to hide specific elements:

ValuePositionContent
'cam_name'Top-leftCamera name
'fps'Bottom-leftFrame count and FPS stats
'ts'Bottom-rightCurrent timestamp
// Hide all overlays
WSPlayer.create('cam1', { ..., noOverlay: true });

// Hide specific overlays (show only camera name)
WSPlayer.create('cam1', { ..., noOverlay: ['fps', 'ts'] });

Event Callbacks:

CallbackDescription
onConnectCalled when WebSocket connection is established
onFirstFrameCalled when first video frame is decoded and displayed
onErrorCalled on connection or decode errors (receives error object)
onDisconnectCalled when connection is closed (not during auto-reconnect)
onReconnectingCalled when auto-reconnect begins
onStallCalled when no data received for stallTimeout ms
onMetadataCalled when server sends metadata (camera info, etc.)

Instance Methods:

MethodReturnsDescription
start()voidStart streaming
stop()voidStop streaming and cleanup
restart()voidStop and restart streaming
connected()booleanReturns true if WebSocket is connected
getFrameCount()numberReturns total frames decoded
getFPS()numberReturns current frames per second
getCamera()objectReturns { id, name }
getStatus()objectReturns full status object for debugging

Static Methods:

// Check if WebCodecs is supported before creating player
const support = WSPlayer.checkSupport();
if (!support.supported) {
    console.error(support.reason);
}

// Factory method (auto-starts the player)
const player = WSPlayer.create('container-id', options);
Custom Implementation: If you need to implement WebSocket H.264 streaming without using WSPlayer.js, refer to the WSPlayer.js source code for a complete working implementation including codec detection and decoder management.
Secure Context Required: WebCodecs API only works in secure contexts:
  • HTTPS - https://yourapp.com
  • localhost - http://localhost (development exception)
Codec Support: Cameras may use different H.264 profiles (Baseline, Main, High). WSPlayer.js detects and handles all supported profiles automatically.
Browser Requirements: WebSocket H.264 requires modern browser support for the WebCodecs API:
  • Chrome 94+ / Edge 94+
  • Safari 16.4+
  • Firefox: Not supported (no WebCodecs)
Error Recovery: WSPlayer.js automatically handles decoder errors, hardware/software fallback, and stream recovery. It will attempt hardware decoding first and fall back to software decoding if needed.
Advantages: WebSocket H.264 offers low bandwidth usage, lowest latency, and hardware-accelerated decoding. Use WSPlayer.js for the simplest integration.

4. Device & Camera Status

GET /ve/onlinestatus

Retrieves the current online status of devices and their cameras.

GET /ve/onlinestatus

Query Parameters

ParameterTypeDescription
idsstringColon-separated device IDs (e.g., "DEV1:DEV2:DEV3")

Example Request

GET /ve/onlinestatus?ids=0A58A9FEAC02:48B02D076C44
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Response

[
  {
    "sDeviceID": "0A58A9FEAC02",
    "fOnline": 1,
    "sBackendID": "backend-01",
    "cams": [
      {"bID": 1, "fEnabled": 1, "fOnline": 1},
      {"bID": 2, "fEnabled": 1, "fOnline": 0}
    ]
  }
]
Polling: Call this endpoint periodically (every 30-60 seconds) to keep status updated in your application.

5. Error Handling

HTTP Status Codes

CodeDescription
200Success
400Bad request (invalid parameters)
401Unauthorized (invalid or expired token)
403Forbidden (no access to requested resource)
500Server error

Error Response Format

{
  "error": "Error message description"
}

Common Errors

ErrorCauseSolution
"Could not find user."Invalid credentialsVerify username/password
"No body provided"Missing request bodySend JSON body with request
401 UnauthorizedInvalid/expired tokenRe-authenticate with /ve/auth
403 ForbiddenNo access to deviceCheck user permissions
