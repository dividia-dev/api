Overview

The Dividia Cloud NVR API provides REST endpoints for integrating with cloud-connected video surveillance systems. This API enables third-party applications to authenticate users, retrieve device and camera information, and stream live video.

Base URL

Production: https://api.cloud.dividia.net
Staging: https://api-staging.cloud.dividia.net

Authentication Method

The Cloud API uses JWT (JSON Web Tokens) for authentication. After login, include the token in all authenticated requests:

Authorization: Bearer <your-jwt-token>

1. Authentication

POST /ve/login

Authenticates a user and returns a JWT token along with all authorized devices and cameras.

POST /ve/login

Request Body

{
  "username": "user@example.com",
  "password": "your-password"
}

Request Parameters

FieldTypeRequiredDescription
usernamestringYesUser email address
passwordstringYesUser password

Success Response

{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "bID": 1,
    "sName": "user@example.com",
    "bRole": 2,
    "bCustomerID": 1
  },
  "customers": [...],
  "projects": [...],
  "devices": [...],
  "cameras": [...],
  "userViews": [...],
  "deviceIdList": ["0A58A9FEAC02", "48B02D076C44"],
  "backendVersion": "2026.1.1"
}

Response Fields

FieldTypeDescription
tokenstringJWT token for authenticated requests (valid 30 days)
userobjectUser details including ID, name, and role
customersarrayOrganizations the user belongs to
projectsarraySites/locations within customers
devicesarrayRecording devices user has access to
camerasarrayCameras with stream source paths
userViewsarraySaved camera view layouts
deviceIdListarrayList of device serial IDs (for token validation)

Error Response

// Invalid credentials
{"error": "Could not find user."}

// Password change required
{"changePassword": true, "user": {...}}
Important: The login response includes all devices and cameras the user has access to. No separate API call is needed to fetch cameras.

Token Usage

Include the JWT token in the Authorization header for all authenticated endpoints:

GET /ve/streamstart?device=0A58A9FEAC02&cam=1&pro=1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Token Expiry: JWT tokens are valid for 30 days. When the token expires, re-authenticate with /ve/login.

3. Live Video Streaming

Streaming Methods

MethodLatencyBandwidthCompatibilityUse Case
HLS 5-15 seconds Medium Excellent (all browsers) Standard viewing, mobile
WebSocket H.264 <1 second Low Modern browsers (HTTPS) Real-time monitoring

HLS Streaming

HLS (HTTP Live Streaming) provides broad compatibility and stable playback.

Step 1: Initialize Stream

GET /ve/streamstart

Query Parameters

ParameterTypeRequiredDescription
devicestringYesDevice serial ID
camintYesCamera number (1-16)
prointYesProfile: 1 (full) or 2 (lower)

Example Request

GET /ve/streamstart?device=0A58A9FEAC02&cam=1&pro=1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Response

{"result": "OK"}

Step 2: Play HLS Stream

After initialization, access the HLS playlist:

GET /uploads/base/hls/{deviceID}-cam{N}-pro{P}_.m3u8

HLS URL Format

// Full URL pattern
https://api.cloud.dividia.net/uploads/base/hls/{deviceID}-cam{cameraNum}-pro{profile}_.m3u8

// Example
https://api.cloud.dividia.net/uploads/base/hls/0A58A9FEAC02-cam1-pro1_.m3u8

JavaScript Example (using hls.js)

// Initialize stream first
await fetch(`${apiUrl}/ve/streamstart?device=${deviceId}&cam=${camNum}&pro=1`, {
    headers: { 'Authorization': `Bearer ${token}` }
});

// Then play HLS
const hlsUrl = `${apiUrl}/uploads/base/hls/${deviceId}-cam${camNum}-pro1_.m3u8`;

if (Hls.isSupported()) {
    const hls = new Hls();
    hls.loadSource(hlsUrl);
    hls.attachMedia(videoElement);
} else if (videoElement.canPlayType('application/vnd.apple.mpegurl')) {
    // Safari native HLS
    videoElement.src = hlsUrl;
}
HLS Library: For non-Safari browsers, use hls.js for HLS playback.

WebSocket H.264 Streaming

WebSocket streaming provides lower latency but requires HTTPS and MediaSource Extensions (MSE).

WebSocket URL Format

wss://api.cloud.dividia.net/{deviceID}-cam{N}-pro{P} 
// Example
wss://api.cloud.dividia.net/0A58A9FEAC02-cam1-pro1

WebSocket Protocol

Message TypeContentDescription
BinaryArrayBufferH.264 NAL units (video data)
StringJSONMetadata: timestamp, motion flag

Metadata Message Format

{
  "ts": 1234567890000,    // Timestamp in 90kHz units
  "motion": true           // Motion detection status
}

Implementation Notes

// Convert timestamp to readable format
const date = new Date((timestamp / 90000) * 1000);
const timeString = date.toLocaleTimeString();
Requirements: WebSocket H.264 streaming requires:
  • HTTPS connection (secure context)
  • Browser with MediaSource Extensions support
  • WebCodecs API (Chrome 94+, Edge 94+, Safari 16.4+)

4. Video Playback (Recorded)

GET /ve/playbackevents

Retrieves recorded events for a camera within a date/time range.

GET /ve/playbackevents

Query Parameters

ParameterTypeRequiredDescription
devicestringYesDevice serial ID
camintYesCamera number
datestringYesDate (MM/DD/YYYY format)
startTimestringNoStart time (HH:MM:SS)
endTimestringNoEnd time (HH:MM:SS)

Example Request

GET /ve/playbackevents?device=0A58A9FEAC02&cam=1&date=03/09/2026&startTime=00:00:00&endTime=23:59:59

Response

[
  {
    "bID": 12345,
    "sDeviceID": "0A58A9FEAC02",
    "sTimeStamp": "20260309120000",
    "sType": "VIDEO",
    "bDuration": 30,
    "bCamera": 1,
    "fCached": true
  }
]

GET /ve/videoevent

Requests a specific video event for playback. This triggers the backend to cache the video.

GET /ve/videoevent

Query Parameters

ParameterTypeDescription
devicestringDevice serial ID
camintCamera number
tsstringEvent timestamp (YYYYMMDDHHMMSS)

GET /ve/videoeventdownloadstatus

Checks the download/cache progress of a video event.

GET /ve/videoeventdownloadstatus

Query Parameters

ParameterTypeDescription
idintEvent ID from playbackevents response

Response

{
  "result": {
    "dCacheProgress": 75  // 0-100 percentage
  }
}

5. Device & Camera Status

GET /ve/onlinestatus

Retrieves the current online status of devices and their cameras.

GET /ve/onlinestatus

Query Parameters

ParameterTypeDescription
idsstringColon-separated device IDs (e.g., "DEV1:DEV2:DEV3")

Example Request

GET /ve/onlinestatus?ids=0A58A9FEAC02:48B02D076C44
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Response

[
  {
    "sDeviceID": "0A58A9FEAC02",
    "fOnline": 1,
    "sBackendID": "backend-01",
    "cams": [
      {"bID": 1, "fEnabled": 1, "fOnline": 1},
      {"bID": 2, "fEnabled": 1, "fOnline": 0}
    ]
  }
]
Polling: Call this endpoint periodically (every 30-60 seconds) to keep status updated in your application.

6. Error Handling

HTTP Status Codes

CodeDescription
200Success
400Bad request (invalid parameters)
401Unauthorized (invalid or expired token)
403Forbidden (no access to requested resource)
500Server error

Error Response Format

{
  "error": "Error message description"
}

Common Errors

ErrorCauseSolution
"Could not find user."Invalid credentialsVerify username/password
"No body provided"Missing request bodySend JSON body with request
401 UnauthorizedInvalid/expired tokenRe-authenticate with /ve/login
403 ForbiddenNo access to deviceCheck user permissions
